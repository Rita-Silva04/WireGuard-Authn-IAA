\section{PAM Orchestration}
\label{sec:pam}

MFA and RBA orchestration runs through PAM: a custom C module
(\texttt{pam\_vpnmfa.so}) decides which factors are required and in what
order, while a Python bridge in \texttt{common/libpam.py} drives
\texttt{pam\_authenticate} from the Flask IdP through \texttt{ctypes}.
This keeps the policy (what is required) strictly separated from the
mechanism (how each factor is verified).

\subsection{The Custom PAM Module}
\label{sec:pam-module}
\texttt{idp/pam\_iaa/src/pam\_vpnmfa.c} compiles to a standard PAM module
shared object:

\begin{lstlisting}[language=bash, basicstyle=\ttfamily\scriptsize]
gcc -Wall -Wextra -fPIC -shared -O2 \
    -o pam_vpnmfa.so pam_vpnmfa.c -lpam
\end{lstlisting}

It is installed in the system PAM module directory.
The service profile \texttt{/etc/pam.d/iaa-vpn} has a single line:

\begin{lstlisting}[language=bash, basicstyle=\ttfamily\scriptsize]
auth required pam_vpnmfa.so
\end{lstlisting}

When the IdP calls \texttt{pam\_authenticate("iaa-vpn",~user)}, the module:

\begin{enumerate}
  \item Reads \texttt{PAM\_USER} and \texttt{PAM\_RHOST} from the item store.
  \item Reads the environment variable \texttt{IAA\_RISK\_SCORE} (an
    integer 0--100) that the Python bridge sets before the call.
  \item Maps the score to a tier: scores below 30 require only password;
    30--59 require password and TOTP; 60 and above require all three
    factors (password, TOTP, FIDO2).
    The module emits a \texttt{PAM\_TEXT\_INFO} message such as
    \texttt{"INFO:tier=L2 score=35"} for the bridge to log.
  \item Walks the required factor list in the fixed order
    \texttt{[password, totp, fido2]}, sending one
    \texttt{PAM\_PROMPT\_ECHO\_OFF} conversation prompt
    \texttt{"FACTOR:<name>"} per factor.
  \item Interprets the response: \texttt{"OK"} advances;
    \texttt{"UNAVAILABLE"} returns \texttt{PAM\_AUTHINFO\_UNAVAIL};
    anything else (including \texttt{"FAIL"}) returns
    \texttt{PAM\_AUTH\_ERR}.
\end{enumerate}

Keeping the tier policy in the C module (rather than in Python) means
a security audit of ``what factors are required'' only needs to read one
file. The PAM module is the single source of truth for factor selection.

\subsection{Driving libpam from Flask}
The Flask IdP cannot call \texttt{pam\_authenticate} directly because
\texttt{libpam} is a C library; we wrote a small \texttt{ctypes} wrapper
in \texttt{common/libpam.py} that exposes
\texttt{pam\_start}, \texttt{pam\_authenticate}, \texttt{pam\_end}, and a
Python-side conversation callback.

The conversation contract is fixed:

\begin{table}[h]
\centering
\caption{PAM conversation contract between the module and the Python bridge.}
\label{tab:pam-conv}
\scriptsize
\begin{tabular}{ll}
\toprule
\textbf{Prompt} & \textbf{Allowed response} \\
\midrule
\texttt{FACTOR:password} & \texttt{OK} / \texttt{FAIL} / \texttt{UNAVAILABLE} \\
\texttt{FACTOR:totp}     & \texttt{OK} / \texttt{FAIL} / \texttt{UNAVAILABLE} \\
\texttt{FACTOR:fido2}    & \texttt{OK} / \texttt{FAIL} / \texttt{UNAVAILABLE} \\
\texttt{INFO:tier=\dots} & (any string, treated as ack) \\
\bottomrule
\end{tabular}
\end{table}

\subsection{Threading Model}
\texttt{pam\_authenticate} is blocking but our browser interaction is
asynchronous: each factor takes a separate HTTP round-trip.
\texttt{idp/pam\_bridge.py} uses \texttt{threading.Event} objects to
park the conversation callback until Flask supplies a result:

\begin{enumerate}
  \item \texttt{start\_authentication(sid, user, ip, score)} spawns a
    worker thread that calls \texttt{pam\_authenticate}.
  \item The conv callback parks on \texttt{prompt\_event} after recording
    the current \texttt{FACTOR:\dots} prompt.
  \item The next Flask route (e.g.\ \texttt{/oauth/mfa/<sid>/totp})
    calls \texttt{wait\_for\_prompt(sid)} and renders the relevant
    factor form.
  \item After verifying the factor, the route calls
    \texttt{submit\_factor\_result(sid, "OK"|"FAIL"|"UNAVAILABLE")},
    which unparks the conv callback and the PAM thread proceeds to the
    next factor or returns.
\end{enumerate}

A 5-minute factor timeout reaps abandoned sessions; Flask handlers use
short \texttt{wait\_for\_prompt} timeouts so no HTTP worker is ever
blocked on PAM indefinitely.
